# chi（ちー）

個人事業主向けの、ローカルで完結する会計ソフト。

## 技術スタック
- Runtime: Bun / Framework: Tauri 2 / Frontend: React + TypeScript
- Icons: Lucide React / Database: SQLite（tauri-plugin-sql）

## 使い方
```
bun install
bun tauri dev     # 開発モードで起動
bun test          # 会計ロジックのテスト
```

## できること（v0.1）
| 画面 | 内容 |
|---|---|
| ホーム | 売上・経費・所得、月別推移、最近の仕訳 |
| 帳簿入力 | 出納帳形式の入力。補助科目ごとの帳簿（例：普通預金 → 銀行別）にも対応 |
| 振替伝票 | 複合仕訳。⌘/Ctrl + Enter で登録 |
| 仕訳日記帳 | 日付・金額範囲・科目・取引先（補助科目）・摘要で検索。削除済みの表示、CSV 書き出し |
| 総勘定元帳 | 科目別・補助科目別の動きと残高 |
| 訂正・削除履歴 | 仕訳の訂正・削除（訂正前／訂正後・理由つき）と、勘定科目・期首残高の変更を一覧。CSV 書き出し（厳密モードのみ） |
| 残高試算表 | 貸借対照表／損益計算書、補助科目の内訳 |
| 家事按分 | 科目ごとの事業割合・根拠メモ。「入力のたびに分ける」か「年末にまとめて振り替える」を科目ごとに選択 |
| 決算書 | 青色申告決算書に近い形の損益計算書・貸借対照表（印刷可） |
| 期首残高 | 1月1日の残高（補助科目別）。差額を元入金で調整 |
| 勘定科目 | 科目の追加・名前変更・非表示、補助科目の管理 |
| 事業者設定 | 屋号・申告種類・消費税・翌年への繰越（補助科目の残高も引き継ぎ） |

日付は `4/15`・`0415`・`15`（当月）のように省略して入力できます。

## 帳簿の保存方式（電子帳簿保存法モード）
帳簿を作るときに次のどちらかを選びます。**あとから変更はできません**（DB のトリガーで拒否）。

| | 電子帳簿保存法に対応（優良な電子帳簿） | 通常 |
|---|---|---|
| 仕訳の訂正 | 訂正前・訂正後を履歴に記録（理由も任意で） | 上書き |
| 仕訳の削除 | 「削除済み」の印をつけ、内容を履歴に記録（伝票番号は欠番） | 完全に削除 |
| 勘定科目・補助科目の名前変更 | 表示中の年度から新しい名前。過去の年度は元の名前のまま。履歴に記録 | すべての年度に反映 |
| 勘定科目・補助科目の追加・非表示・削除 | 履歴に記録 | 記録しない |
| 期首残高の変更（繰越処理を含む） | 変更前後の金額を履歴に記録 | 記録しない |
| 「訂正・削除履歴」画面 | あり | なし |

厳密モードの仕組み
- 仕訳は物理削除しない。登録・訂正・削除のたびに、その時点の仕訳の写し（科目名はその年度の名前）を `entry_history` に積み上げる
- 科目・補助科目の名前は `master_names` に「何年から何という名前か」で持つ
- より新しい年度がある状態で、過去の年度の名前は変えられない
- 科目などの変更は `master_history` に記録
- `entry_history` / `master_history` は SQLite のトリガーで UPDATE / DELETE を禁止。削除済みの仕訳も変更不可
- **限界**：SQLite ファイルを外部ツールで直接編集すること自体は防げない。ソフトとして保証できる範囲と、
  法令上の保存要件との差は、研究上の論点として残している（下の「足りていないところ」参照）
- **消費税**：免税事業者（税込経理）のみ。課税区分・経理方式・税区分は画面にあるが、グレーで選べない状態

## 科目と補助科目
- 勘定科目は区分ごとのコード範囲で追加できます（資産 100〜199、負債 200〜299、資本 300〜399、
  収益 400〜499、売上原価 500〜599、経費 600〜699、専従者給与等 700〜799）→ 1区分あたり最大100科目
- 初期科目は削除・区分変更できません（名前は変更可）。現金・事業主貸・事業主借・元入金は固定です
- 追加した科目でも、使用済みなら削除できません（非表示にはできます）
- 補助科目は1科目あたり100件まで

## 開発方針
- **個人・法人は1つのソフトで扱う**：将来は、帳簿を作るときに「個人／法人」を選ぶ（保存方式と同じく、あとから変更不可）
- **法人対応までに守ること**（あとで大きな作り直しをしないため）
  - 会計期間の開始日・終了日は、必ず `lib/accounting.ts` の `yearStart` / `yearEnd` を通す（日付を直接 `1月1日`・`12月31日` と書かない）
  - 個人特有の処理（元入金の再計算、事業主貸・事業主借の扱い、青色申告特別控除）は1か所にまとめ、「個人の場合の処理」として分けておく
  - 決算書・試算表の見出し（「資本」「元入金」など）は画面に直接書かず、区分の定義（`constants/accounts.ts`）から引く

## フォルダ構成
```
src/
  lib/accounting.ts     会計ロジック（純粋関数・テストあり）
  lib/format.ts         金額・日付の入力変換
  db/schema.ts          テーブル定義と、履歴を守るトリガー
  db/repo.ts            SQL はすべてここ
  constants/            勘定科目マスター、消費税の選択肢、アプリ設定・上限
  context/AppContext    開いている帳簿・年度・科目を各画面へ配る
  components/           入力部品（科目・補助科目・金額・日付・摘要・税区分）など
  features/             画面ごとのフォルダ
```

## データファイル
- `書類/chi/*.chi` が帳簿ファイル（1ファイル = 1事業者、複数年を保存）
- 開くたびに `書類/chi/Backup/` へ `.chib` として自動バックアップ

## 名前を変えるときに触る場所
`src/constants/appConfig.ts`（表示名・読み・フォルダ名・拡張子）、`src-tauri/tauri.conf.json`（productName・identifier・ウィンドウタイトル）、
`package.json` / `src-tauri/Cargo.toml` の name、`src-tauri/src/main.rs` の lib 名、`index.html` の title、`src/features/start/StartScreen.tsx` と `public/logo.svg` のロゴ。
アプリのアイコンは `app-icon.png` を差し替えて `bunx tauri icon app-icon.png -o src-tauri/icons` で作り直す。
